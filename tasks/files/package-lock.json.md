# Implementation brief for `package-lock.json`

## Scope

Regenerate this existing file through npm after the package manifest adds the pinned SQLite runtime/type packages, moves tsx to runtime dependencies and changes scripts/engine declaration. The lockfile captures the exact transitive dependency graph and platform installation metadata used by `npm ci`, including correct production/dev flags for the moved runner.

## Procedure and review

Run the repository's npm version with the edited package manifest. Review the diff for new SQLite/prebuild dependencies, matching root manifest metadata and the new type package. Avoid manually composing integrity values, resolved tarball URLs or dependency graphs. Avoid broad npm update commands that upgrade unrelated React/Vite/provider packages.

The current native SQLite release must install and load on the supported Windows development machine and the intended deployment platform. If the native dependency requires a source build, record the actual installation error and choose the smallest supported recovery without changing the feature's persistence model silently.

## Verification

- [ ] `npm ci` succeeds from the regenerated lockfile in a fresh install context.
- [ ] `node` can load the installed SQLite library and open a temporary database.
- [ ] Runtime, typecheck, build and focused integration tests use the same resolved package versions.
- [ ] The lockfile introduces no secrets, private local paths or unrelated dependency upgrades.
